# SM HBD CRM: notes for Claude and other AI coding tools

Sales / revenue / staff-performance CRM for SecondMedic's healthcare business-development team. One repository,
`secondmedic-ops/SM-HBD-CRM`; `main` is production. **Read `PROJECT.md` first** (URLs, roles, commands).
Built on the sb-spring-cf-stack skill; SM ERP (`secondmedic-ops/SM-ERP`) is the reference for the pipeline files.

## Layout

| Path | What it is | Who edits it |

## Rules

- **Ship only with `SHIP.bat`** (`node scripts/ship.mjs "what changed"`): guard, lint, local DB from migrations, Worker
  typecheck + unit tests, rehearsal (real Worker on that DB: schema check, 401 without login, ~100 API checks,
  contract), frontend calls vs contract + typecheck + build, migrations, Hyperdrive, one `wrangler deploy`, smoke, record.
- **Every endpoint is one line in `cloudflare/src/api/routes.ts` with its roles.** Only health/version are public;
  `'login'` only for `/api/v1/me`. Add API checks for new endpoints in `cloudflare/test/api.itest.mjs`.
- **Scope lives in the API, not the screens**: `services/scope.ts` (ADMIN / ACCOUNTS all; INCHARGE their team =
  themselves + everyone below them via `incharge_id`, followed down the chain (`teamIds` in auth.ts, recursive SQL); STAFF own rows and own clients, daily updates their team). STAFF JSON
  never carries `cost`; STAFF edits keep the saved cost. Screens filter the incharge view with `inTeam()` from the context.
- **Clients** (`services/clients.ts`, `src/components/ClientsTab.tsx`): each client has an owner (staff); same scope;
  a client outside scope answers 404. Visits in `client_visits`. Revenue entries may carry `client_id`.
- **Team structure**: ADMIN sets Reports to in Staff mapping; INCHARGE adds / edits / removes their own Team members and
  their logins in My team (`src/components/MyTeamTab.tsx`); never role, department or incharge.
- **Revenue and outstanding stay in step** (`domain/payments.ts`, unit-tested in `test/payments.test.ts`): an entry not
  fully paid gets one outstanding row (amount = entry amount - received up front); a payment on that row raises both
  `amount_paid` and the entry's `amount_received`; editing an entry keeps payments already collected. Status is
  derived from the numbers (Paid / Partly paid / Outstanding), never stored.
- **Change the data model in the same push:** migration (`YYYYMMDDHHMMSS_name.sql`, idempotent, RLS on), `SCHEMA` in
  `cloudflare/src/db.ts`, the service / JSON shape, `src/types.ts` + `src/api.ts`. Drops / renames need a later
  `[contract]` push.
- **Every data change is audited** in the same transaction (`services/audit.ts`), without client names, staff names,
  emails, update text or images.
- **Money is exact**: big.js in `domain/money.ts`; `numeric(14,2)` in SQL; today = `todayIst()`.
- **Images**: data URLs (PNG / JPEG / WEBP / GIF, max ~1 MB) in `public.attachments`; lists send only ids.
- **Design** (new or changed UI): no gradients, shadows, glass blur, rounded-lg/xl corners, lucide icons, emojis,
  hover animations, coloured left stripes, pure white page background; skeleton loaders for loading. The screens from
  AI Studio still use several of these; fix them only when asked.
- Retired files go in `scripts/obsolete.txt` (SHIP.bat removes them).
